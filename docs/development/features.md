# Product features and support

Paths in backticks are relative to the repository root unless stated otherwise.

The desktop feature catalog is in `src/Kitopia.Desktop.Features/Services/Plugin/KitopiaFeatures.cs`. The main navigation items are in `src/Kitopia.Desktop.Features/ViewModel/Main/MainWindowViewModel.cs`; `src/Kitopia.Desktop/Program.cs` registers the corresponding views.

| Capability | Main implementation |
| --- | --- |
| Search and launcher | `src/Kitopia.Desktop.Features/Search/`: app/file/scenario search, pinyin, ranking, history, pins, input recognition, result actions and previews. |
| Local semantic search and indexing | `src/Kitopia.Desktop.Features/Indexing/` and `Search/Semantic/`: EmbeddingGemma 2 ONNX Q4 text/image embeddings (float32 activations, shared 768 dimensions), document extraction, SQLite/sqlite-vec storage, maintenance and status. Model assets are supplied by the separate `KitopiaSemanticSearch` plugin. |
| File preview | `Search/Preview/`, `Search/ViewModels/MouseQuickWindowViewModel.cs`, desktop `Controls/FilePreviewControl.axaml`, and Windows `NativeFilePreviewHost.cs`. |
| Screenshots | Desktop `Windows/ScreenCaptureWindow.axaml`, `Controls/Capture/`, long screenshot UI, and Windows `ScreenCapture/`: selection, HDR capture, annotation, color picking and stitching. |
| OCR and translation | Desktop features `Ocr/` and `Translation/`; Windows selection access in the platform project and selection translation UI/service in the desktop host. |
| Device chat and file sharing | `src/Kitopia.Feature/` owns discovery, identity, protocol, TCP/TLS, messages and transfers; `src/Kitopia.Feature.Avalonia/` owns reusable chat UI. |
| Custom scenarios | `src/Kitopia.Desktop.Features/CustomScenario/`: graph, execution, persistence, editor view models, triggers and scenario market. Desktop `Windows/TaskEditor/` owns the editor window. |
| Plugin host and market | `src/Kitopia.Desktop.Features/PluginHost/`: discovery, dependencies, loading/unloading, packages, downloads, market and plugin settings. |
| Models and system tools | `Services/Onnx/`, model manager, hotkey manager, file lock UI, LAN share window, shell integration, settings and account services. |
| KitopiaEx extensions | `plugins/KitopiaEx/`: screenshot OCR/QR/translation/pinning/saving, translation and window search analyzers, image/video compression, batch file renaming and scenario nodes. Search image actions (save, OCR, pin and compress) belong to KitopiaEx; the host only identifies clipboard images. Batch renaming previews conflicts before moving files; optional image compression creates renamed copies while preserving source images. Image/video compression and batch renaming register Explorer menu entries and SDK startup handlers on plugin enable and remove them on disable; the host routes selected paths after plugins are ready. Media libraries and tools come from the separate optional `KitopiaFfmpeg` plugin. Without it, ordinary batch renaming and other extensions remain available; plugin management and details show optional dependencies as a compact badge beside the plugin status. Clicking it opens a scrollable popup with feature explanations and download/enable actions without changing the surrounding layout. An already-open batch rename window receives FFmpeg availability changes without losing its inputs. |

### Defaults and Support Scope

- Default hotkeys are defined in `src/Kitopia.Desktop.Features/Services/Config/KitopiaConfig.cs`: search `Alt + Space`, screenshot `Ctrl + Alt + Q`, selected file preview `Space` in `explorer.exe`, selection translation `Ctrl + Alt + Y`, and window topmost `Ctrl + Alt + T`.
- Automatic selection translation uses a mouse drag-release trigger. Hotkey models support keyboard/mouse triggers and process scopes.
- The former mouse quick entry now presents file previews; do not describe it as a general mouse gesture system without checking the implementation.
- Windows is the primary desktop target. Linux has platform adapters but does not have every Windows feature.
- Desktop settings provide `hideSearchWindowBorder` (default off): `SearchWindow` applies `WindowDecorations.None` immediately and on creation, leaving internal controls and styles unchanged.
- Desktop search settings provide `verticalEmptySearchResults` (default off). With an empty ordinary query, `SearchWindowViewModel.LoadLastCore` sends pins, ranked history and input-analyzer suggestions to the existing result list for a single vertically scrolling layout; file rows show their absolute path. `ProcessInputData`, pin changes and live setting changes reuse that list and its selection, keyboard navigation and activation. Inline actions without an `OnlyKey` have no pin control and cannot be persisted as pins. Typing a query or entering directory search retains the existing layout; turning the option off restores the horizontal shortcut strip. History ranking and limits still apply, and the SDK is unchanged.
- Startup task lookup enumerates the root task folder with `TASK_ENUM_HIDDEN` and matches the task name. Missing tasks return null without throwing: COM `GetTask` maps a missing registration to `FileNotFoundException`, which interrupts exception-enabled debugging even when caught. Query failures still propagate to startup registration error handling.
- Windows automatic startup uses `IApplicationService.ChangeAutoStartAsync`, implemented in `ApplicationService.Startup.cs`. Normal startup retains the current-user Run entry. `preferEarlyStartup` (default off, shown only while automatic startup is enabled) replaces it with a per-user-SID, immediate interactive logon task with `LeastPrivilege` and normal process priority. This does not guarantee ordering before every other startup application. Turning automatic startup off removes both entries while retaining the preference. Settings await registration before saving and restore the toggle on failure/cancelled UAC. The singleton service serializes registration transactions with `SemaphoreSlim`; explicit settings requests supersede queued startup reconciliation. Startup reconciliation never requests elevation; it reports failures for repair in Settings. This path waits for `schtasks.exe` completion and must not reuse Everything's fire-and-forget, highest-privilege launch shortcut.
- Windows file lock termination is owned by `src/Kitopia.Desktop.Platform.Windows/Services/FileLocksmithService.cs`. It first terminates processes with the current permissions; access denied for a selected process is retried through the system `taskkill.exe`, with one UAC prompt per batch. This includes access-denied errors wrapped by `Process.Kill(entireProcessTree: true)` in an `AggregateException` when the root is still alive. It waits for the elevated operation and reports cancellation or a nonzero exit code as failure. Already elevated clients do not prompt again. Partial process-tree failures after the parent exits continue to report failure: its PID cannot reliably identify surviving descendants for an elevated retry. All file lock termination actions, including unlock-and-delete, reuse `IFileLockService.UnlockFileAsync`. `IDesktopShell.RunAsAdmin` is for fire-and-forget launches and cannot supply the completion result needed here.
- Directory scans reuse `FileLocksmithService.QueryRestartManagerForFiles` for files that probe as locked but have no identified process, including owners whose handles cannot be duplicated. Identified owners replace PID-zero placeholders. File, directory and batch unlock commands in `FileLocksmithWindowViewModel` retry owner discovery through `IFileLockService.CheckFileLocksAsync` when a locked record still has no usable PID; they report unresolved owners and termination failures instead of silently skipping them. Directory unlock includes handles on the directory itself. Operation results are shown after the follow-up scan; normal automatic refresh can later replace them with scan statistics.
- Successful file deletion immediately removes matching monitor records and selection. Windows scans omit paths confirmed missing, including explicit targets and stale handle records; target paths remain monitored so recreated files can appear again. Refresh requests during an active scan are coalesced into a subsequent scan, and the superseded snapshot is discarded.
- Explorer integration is delivered by the standalone Microsoft Store Kitopia Companion MSIX. Its release/debug manifests and `src/ContextMenuDll/SparsePackage.appxmanifest` register modern `IExplorerCommand` and classic `IContextMenu` menus for files, directories and directory backgrounds in the same package. Both reuse `KitopiaExplorerCommand`, configuration and `CommandHelper.ExecuteCommand`; the classic `KitopiaClassicContextMenu` CLSID provides Debug comhost mapping and is accepted by the Release factory. Every `desktop9:ExtensionHandler` requires a matching `com:SurrogateServer/com:Class`; do not substitute in-process-only registration. The surrogate drops HBITMAP alpha, so `KitopiaExplorerCommand.Legacy.cs` composites straight BGRA against the current Windows menu background before marshalling. It samples `Menu`/`DarkMode::Menu` theme backgrounds, preserves high-contrast system colors, and retains bitmaps with `SafeHandle`, cached by path and background color. This removes black transparent areas but is an opaque background composition: hover/selection backgrounds or host-specific menu themes can differ. Missing icons leave commands available. The desktop Avalonia icon pipeline does not provide native menu HBITMAPs. Debug explicitly copies the generated comhost because its template size/timestamp can remain unchanged after adding a CLSID. Updating only the desktop client does not change Companion registration; all menu integration updates through the Store package, without a separate installer.
- Android mobile focuses on device chat and file transfers. The Android project targets API 36 with minimum API 23 and produces APKs. iOS has a host project but is not packaged by the current release pipeline.
- OCR and semantic matching run locally with models and a usable ONNX backend. Translation and online markets use network services.
- Desktop translation defaults to the free Index-Translate online API (Index-Translate-35B-A3B); Microsoft Translator remains selectable through `KitopiaConfig.translationProvider`. Selection translation and KitopiaEx translation entries share the selected host service.
- Selection translation uses the host's `ISelectionTextTranslator` contract. Every Index-Translate selection uses one API request with the same dictionary/translation system instructions and completed examples localized to the target language. The model returns pronunciation, parts of speech, meanings and a bilingual example for words, fixed phrases, idioms and proper names; sentences, truncated clauses, lists and paragraphs receive only a translation. There is no separate classification request or length/word-count mode switch. Ordinary `PluginCore.ITranslationService` calls and Microsoft selection translation keep their normal translation response.
- Desktop update checks exclude prereleases by default. `KitopiaConfig.allowPrereleaseUpdates` enables them; both GitHub's prerelease flag and the NuGet version label are checked, and draft releases are always excluded.
