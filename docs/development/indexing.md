# Search and indexing

Paths in backticks are relative to the repository root unless stated otherwise.

## Behavior and contracts

- Indexing/search: `Indexing/IIndexService.cs` also defines `ISearchEntryIndex` and `IIndexMaintenanceService`; app indexing and Everything contracts are in `Search/`.
- Ordinary interactive searches first run the complete name/pinyin search for applications, plugins and managed files together, then publish that group and update display state before semantic debounce or inference. Startup rebuilds the pinyin searcher after the initial application/plugin batch, before managed-file and semantic indexing, so freshly loaded applications participate in the ordinary first pass. `SearchAsync` can reuse that same query's prepared pinyin results, avoiding a second file-database scan. When there are no lexical matches, note/web actions are published in that same first stage; a failed, canceled or empty semantic search keeps them, while semantic matches replace them. Semantic results merge afterward under the existing query-version and cancellation checks; retained lexical rows reuse their view items and move in place so a selected application/file and its list/preview layout survive semantic reordering. The view restores focus to a moved row only if the window is active and focus has become empty; input-box focus is preserved. Input-analyzer rows keep their separate positions. Sufficient lexical matches still skip semantic fallback. Embedding processor creation uses BCL lazy initialization independent of the application-entry lock; missing model files are retried on a later request.
- Interactive Everything results load in pages of 100. `EverythingFileListControl` observes the DataGrid's vertical scrollbar and sends column sort changes through the search view model to `IAppToolService`. Everything owns sorting across all matches; changing the sort restarts at offset zero, and stale queries must not append results or reset the new query's loading state.
- `EverythingClient.Search` is the Windows query entry point. It returns a materialized page through `IAppToolService`, propagates cancellation while waiting for the shared SDK gate and reading results, and reuses `EnsureQuerySucceeded` to distinguish query failures from empty results. A synchronous native query already in progress cannot be interrupted; canceled results and failures must not update newer searches. Filesystem metadata fallback runs after releasing the SDK gate.
- Everything availability is checked off the UI thread when the search window opens and when its prefix is entered without a query. Normal queries also update availability. Checks propagate cancellation through `IEverythingAvailabilityService` and the shared SDK gate; changing the query, starting a page or hiding the window invalidates older probes so they cannot overwrite newer results. Reopening checks again. The auto-start setting is not an availability signal.
- Search status uses a compact, theme-aware indicator: checking, connected or unavailable. Healthy status is hidden outside Everything mode; failures remain discoverable without displacing ordinary search results. The details reuse `Kitopia.Feature.Avalonia.Controls.HoverFlyoutButton` for hover/click access, pointer crossing and dismissal, and the same warning indicator/card/presenter/action themes as hotkey and LAN compatibility warnings (see the architecture guide). Search supplies only its localized content and commands: an independent check and the existing same-page retry. A successful query, including zero matches, clears the failure state. The indexing options `useEverythingForIndexing` and `everythingIndexIncludePatterns` do not restrict prefix searches. They and `everythingSearchPrefix` retain their original JSON property names for configuration compatibility.
- Everything prefix searches keep the full result list by default; preview remains available through the manual toggle. The search preview uses a draggable middle splitter to adjust the list and preview widths, and closing preview restores the full list width.
- Explorer folder search uses the configurable `explorerSearchHotKey`, defaulting to any printable character without Ctrl/Alt/Win. It only triggers in a Windows Explorer file list, preserving navigation keys, address/search fields and rename editing. `HotKeyImpl` reuses the shared input hook and captures the first character using the foreground keyboard layout; `ExplorerFileSelection.GetSelection(directoryOnly: true)` reuses its active, visible shell view and COM lifetimes to read the filesystem directory, including the active Explorer tab. Virtual locations without a filesystem path skip the popup and return the initial character through the existing SharpHook event simulator; simulated characters do not retrigger any-character shortcuts. `SearchWindow.ShowDirectorySearch` reuses the existing search window and Everything controls, anchors inside the Explorer window's bottom-right corner, constrained to its intersection with the display work area and sized to fit with a 16-DIP inset, and keeps `SearchWindowViewModel.DirectorySearchPath` separate from editable text. Folder search starts directly with the borderless search input, without a title or directory header. The quoted directory scope and grouped query survive paging, sorting and empty input; opening ordinary search clears that scope. Everything availability, cancellation, preview and opening files retain their existing paths.
- Windows application discovery and shortcut indexing live in `src/Kitopia.Desktop.Platform.Windows/AppTools/AppIndexer.cs`; `AppToolService` exposes them through the existing search contract.
- Application usage sampling reads Windows process creation and CPU times together through `AppToolService.ReadProcessTimes`, injected into `ProcessUsageService` at the desktop composition root. It reuses Vanara's limited-information process handle and checks native failure returns, so protected processes do not repeatedly throw managed `StartTime`/CPU access-denied exceptions. Unreadable times preserve any available memory reading, discard that PID's CPU baseline and show CPU as unavailable; a recovered or recycled PID needs a fresh baseline. Other platforms use the sampler's BCL fallback. Native calls remain in the Windows adapter.
- Document text vectors are stored by file key and chunk index in `IndexVectorStore`. Images use EG2 image embeddings without OCR; old OCR text vectors are removed when the index database opens while image/document vectors, file sources and fingerprints survive. PP-OCRv6 small remains available for screenshots and explicit OCR operations. Search groups document chunk hits by file using the highest similarity; replacement, copying and deletion must include every chunk. Normal indexing uses at most 1024 tokens per chunk, including title/prompt/special tokens, with 48 tokens of content overlap. Text batches contain at most four items and a quadratic attention budget allows only one 1024-token item at a time. Normal text inputs are padded to power-of-two lengths up to 1024, with masks excluding padding, to reuse a small set of arena shapes. The model still accepts up to 8192 tokens for explicit calls. The model ID includes the chunking policy so old vectors are replaced during incremental indexing while file sources and fingerprints are preserved.

## Storage and benchmarks

- The semantic eligibility rule is shared through `SearchIndex.ShouldSearchSemantically`.
- The current vector/index database is `index.db` under that root. Do not reintroduce the legacy `search-rag.db` path into the current index store.
- EmbeddingGemma 2 Q4 assets live under `EmbeddingGemma2`. Queries use `task: search result | query: `; documents use `title: {title or none} | text: {content}`; images have no text prompt. Older vector dimensions are invalidated while managed file sources and file fingerprints remain for incremental rebuilding.
- Image retrieval benchmarks reuse the README feature images under `docs/assets/README/`, selected by the screenshot annotations in `tests/KitopiaBenchmark/EmbeddingComparison/image-queries*.json`.
