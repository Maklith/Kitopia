# Client localization

The desktop client and shared mobile UI use JSON language dictionaries in
`Kitopia.Feature/lang`. Dictionary keys are stable ASCII identifiers such as
`lang.kitopia.cancel`; translated text belongs only in dictionary values.
`zh-CN.json` is the fallback dictionary; `en-US.json` provides English.

Choose the display language in Settings. The desktop stores the culture code in
`KitopiaConfig.language`; an empty string follows the operating system UI language.
Regional cultures use a matching language dictionary, and unsupported languages
fall back to Simplified Chinese. The mobile client follows the system UI language.

## Adding text

Add the same key to each dictionary. Use numbered placeholders for variable text,
preserving their indexes and format specifiers in translations.

```csharp
Lang.Get("lang.kitopia.cancel");
Lang.Format("lang.kitopia.value_plugins", count);
```

```xml
<Button Content="{DynamicResource lang.kitopia.cancel}" />
<TextBlock Text="{lang:Lang 'lang.kitopia.value_plugins', Value={Binding Items.Count}}" />
```

For formatted bindings, declare:

```xml
xmlns:lang="clr-namespace:Kitopia.Feature.Avalonia.Localization;assembly=Kitopia.Feature.Avalonia"
```

Static UI resources and formatted bindings refresh when the language changes.
Code-created settings labels refresh from `Lang.Current` when the language changes.
User content, persisted identifiers and protocol fields retain their original values.
New notifications use the currently selected language. Keep keys unchanged when
editing a translation. Display metadata (`ConfigName`, `ConfigField`, `Feature`,
`ScenarioMethod`, `Capture`) must use dictionary keys. Enum display names can use
`[Description("lang.kitopia.settings.some_option")]` without renaming enum members.

## Plugins

Plugins reference **only `Kitopia.Desktop.PluginSdk`**. They use
`PluginCore.Localization.Lang` and the SDK's XAML extension, with no reference to
`Kitopia.Feature` or any desktop host assembly:

```csharp
using PluginCore.Localization;
Lang.Get("lang.kitopiaex.translate");
Lang.Format("lang.kitopiaex.messages.window_value", title);
```

```xml
xmlns:lang="clr-namespace:PluginCore.Localization;assembly=PluginCore"
<TextBlock Text="{lang:Lang Value={Binding Name}}" />
```

Embed dictionaries in the plugin project:

```xml
<EmbeddedResource Include="lang\*.json" />
```

The resource name must be `<AssemblyName>.lang.<culture>.json`. Set `LogicalName`
explicitly when the root namespace differs from the assembly name. Plugin keys
use `lang.<lowercase-assembly-name>.*`; KitopiaEx uses `lang.kitopiaex.*`.
Provide `zh-CN.json` and `en-US.json` with identical keys and format argument indexes.
The host registers dictionaries before loading plugin metadata and configurations,
then removes them on unload. It retains only parsed strings, allowing plugin
assemblies to be collected. Missing translations fall back to the plugin's Chinese
dictionary; unknown keys and external plugin text are displayed unchanged.

Register type labels through `Kitopia.TypeNames[type.FullName!] = "lang.kitopiaex.some_type"`.
The old `_i18n` field remains for binary compatibility; new plugins must use
`TypeNames` with dictionary keys. Do not change feature IDs, callback names or
serialized type names. When migrating a scenario method's old display name to a
key, explicitly keep its original `Id` so existing saved scenarios still resolve it.
`ScenarioMethodCategory.Name` can represent a category path; use `DisplayName`
for a localized label when preserving an existing path.
When loading saved plugin nodes, the client resolves their original method ID and
updates default titles and parameter labels from the current language keys.
Customized labels, connector references and parameter values are preserved.

## Adding a language

Add `<culture-code>.json` to `Kitopia.Feature/lang`, using the existing keys and
the culture's native translations. The project embeds these files and discovers
language choices automatically; no registration class is required. Missing
translations fall back to Chinese, and unknown keys are shown as-is.

Run localization and settings regression tests:

```powershell
dotnet test KitopiaTest/KitopiaTest.csproj --filter "FullyQualifiedName~LocalizationTests|FullyQualifiedName~SettingPageVisibilityTests"
```
