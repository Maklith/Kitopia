# EG2 Q8 / Q4 对比记录

测试日期：2026-10-08。Windows 11，i7-13700，约 48 GB 内存，
ONNX Runtime 1.28.0 CPU，8 个推理线程，关闭 CPU memory arena。
三组模型分别在独立进程中依次运行。

## 中文样本与结果

文本：T2Retrieval 固定抽样 128 条中文查询、1,643 篇候选文档，
包含这些查询的全部相关文档和 1,024 篇随机干扰文档。
图片：30 张公开样例、11 张仓库截图，50 条人工标注的中文查询。

| 模型 | 文本首位命中 | 文本 Recall@10 | 文本 nDCG@10 | 图片首位命中 | 图片 Recall@10 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 当前 BGE-small-zh-v1.5 + Chinese-CLIP RN50，均为 INT8 | 95.3% | 91.5% | 0.9231 | 72.0% | 90.0% |
| EG2 Q8 | 93.8% | 92.3% | 0.9295 | 90.0% | 100.0% |
| EG2 Q4 | 93.8% | 92.6% | 0.9292 | 90.0% | 100.0% |

| 图片类别 | 当前 CLIP | EG2 Q8 | EG2 Q4 |
| --- | ---: | ---: | ---: |
| 普通照片，31 条查询 | 30/31 | 31/31 | 31/31 |
| 视觉文档，11 条查询 | 6/11 | 7/11 | 7/11 |
| 应用截图，8 条查询 | 0/8 | 7/8 | 7/8 |

10,000 次配对 bootstrap：Q8 相比当前模型的文本 nDCG@10 差值为
`+0.0064`，95% 区间 `[-0.0176, +0.0299]`；Q4 为 `+0.0062`，
区间 `[-0.0184, +0.0304]`。区间都包含零，不能据此认定中文文本检索明显提升。
两种 EG2 的图片首位命中提升均为 18 个百分点，区间为 `[+6, +30]` 个百分点。
Q4 和 Q8 的文本 nDCG 差异区间也包含零，图片首位命中情况完全一致。

## 性能

以下为预热后的纯 ONNX 推理，排除解码、分词和预处理。
文本查询为单条查询、三轮测试；文档编码为每批 8 篇；图片逐张编码。
EG2 图片耗时包含视觉编码器和文本主干。

| 模型 | 权重文件，MiB | 文本查询中位 / p95，ms | 图片查询中位，ms | 文档编码，篇/秒 | 单图编码中位，ms |
| --- | ---: | ---: | ---: | ---: | ---: |
| 当前模型组合 | 97.2 | 0.98 / 1.39 | 30.52 | 107.02 | 87.68 |
| EG2 Q8 | 486.0 | 179.62 / 197.07 | 188.23 | 5.78 | 2787.97 |
| EG2 Q4 | 270.5 | 16.94 / 21.41 | 18.00 | 6.38 | 2118.03 |

| 模型 | 峰值 RSS 增量，MiB | 峰值 private memory 增量，MiB |
| --- | ---: | ---: |
| 当前模型组合 | 223.3 | 212.7 |
| EG2 Q8 | 621.6 | 753.0 |
| EG2 Q4 | 612.9 | 885.4 |

内存增量以完成预处理、尚未加载 ONNX session 的进程为基准，每 20 ms 采样。
全部必要模型 session 同时保留。Q4 下载体积减少，但本次峰值 RSS 与 Q8 接近；
权重大小不能等同于峰值运行内存。Python 进程的绝对内存包含 PyTorch 和缓存输入，
这些数值不能直接预测 C# 应用的完整内存占用。

## 中文结论与限制

- 在这批样本中，EG2 的中文文本检索与当前 BGE 基本持平，图片收益主要来自截图。
- Q4 与 Q8 检索效果接近，Q4 文本查询约快 10.6 倍，权重小约 44.3%。
  Q8 在这批数据上没有体现足以抵消 CPU 成本的质量优势。
- 如果继续接入 EG2，优先考虑 Q4，并评估图片编码的后台吞吐量和 GPU 加速。
  当前证据不足以支持仅为中文文本效果而全量替换 BGE。
- 文本候选集是公开数据的子集，随机干扰文档可能偏容易；这不是完整 C-MTEB 分数。
- 图片样本小且为公开 fixture，不能推广为通用中文图片检索准确率。
- 图片比较仅含原生视觉向量，不含当前应用已有的 OCR+BGE、文件名匹配和融合排序。
  当前 CLIP 截图分数不代表 Kitopia 的整体截图搜索效果。
- 文档仅编码截断后的 256 token，没有整文件分块平均；查询最多 128 token。
  不同分词器可容纳的内容不同，EG2 的 8K 长上下文优势未测试。
- 本次使用 Python ONNX Runtime，尚未验证 .NET 混合类型输入的插件接入或 GPU 性能。

基线准备时发现 Chinese-CLIP 词表中的合法 Unicode 空白词元被 `Trim()` 变为空词元，
可能导致未知词分词死循环。本次基线包含保留词表原始行的修复及回归测试。

复现命令和完整方法见同目录 `README.md`。本地 `artifacts/embedding-comparison/`
保存完整报告、每条查询前 10 个结果、向量、模型 SHA256 和数据来源版本。
EG2 ONNX 修订：`daa72c51243991dfcaf9f9137d2c573d8f7790c0`。

## 英文补测

文本使用 SciFact 全部 300 条测试查询和全部 5,183 篇候选文档，
共 339 条相关性标注；标题和摘要拼接后按相同的 256 token 上限编码。
这次使用完整候选语料，不抽取随机干扰文档。该数据以科研英语为主，
不能代表所有英文场景，也不能与上面的中文数据集分数直接比较。

图片复用上轮相同模型的 41 张图片向量，重新编码 50 条英文查询。
英文查询由中文查询翻译而来，相关图片和类别标注保持一致；其中 8 条为
英文搜索中文应用界面的跨语言查询。已核对缓存图片顺序、路径、模型 SHA256，
并确认新结果里的图片向量与上轮完全一致。当前基线保留生产分词器、
大小写处理和中文 BGE 查询提示，没有为本次英文测试调整输入策略。

| 模型 | 文本首位命中 | 文本 Recall@10 | 文本 nDCG@10 | 图片首位命中 | 图片 Recall@10 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 当前 BGE-small-zh-v1.5 + Chinese-CLIP RN50，均为 INT8 | 14.3% | 33.8% | 0.2321 | 36.0% | 70.0% |
| EG2 ONNX Q8 | 76.0% | 92.6% | 0.8388 | 92.0% | 100.0% |
| EG2 ONNX Q4 | 75.0% | 93.1% | 0.8343 | 94.0% | 100.0% |

| 英文图片查询类别 | 当前 CLIP | EG2 Q8 | EG2 Q4 |
| --- | ---: | ---: | ---: |
| 普通照片，31 条查询 | 15/31 | 31/31 | 31/31 |
| 视觉文档，11 条查询 | 2/11 | 8/11 | 9/11 |
| 中文界面截图，8 条查询 | 1/8 | 7/8 | 7/8 |

10,000 次配对 bootstrap：Q8 相比当前模型的英文文本 nDCG@10 差值为
`+0.6067`，95% 区间 `[+0.5586, +0.6541]`；Q4 为 `+0.6022`，
区间 `[+0.5528, +0.6500]`。两种 EG2 在这组英文任务上都有明显提升。
Q4 相比 Q8 的差值为 `-0.0045`，区间 `[-0.0166, +0.0081]`，
没有观察到稳定的英文文本排序差异。

Q8、Q4 的图片首位命中相比当前模型分别提高 56、58 个百分点，
区间分别为 `[+42, +70]`、`[+44, +72]` 个百分点。
Q4 比 Q8 多命中一条查询；这个小样本不足以据此认定 Q4 图片质量更好。

| 模型 | 英文文本查询中位 / p95，ms | 英文图片查询中位 / p95，ms | 文档编码，篇/秒 |
| --- | ---: | ---: | ---: |
| 当前模型组合 | 1.76 / 2.81 | 31.83 / 38.82 | 99.65 |
| EG2 Q8 | 187.29 / 199.44 | 181.24 / 189.90 | 5.59 |
| EG2 Q4 | 22.12 / 30.08 | 17.60 / 20.42 | 6.73 |

Q4 的英文文本查询约快于 Q8 8.5 倍，而检索质量接近，仍优先考虑 Q4。
文档批量编码的速度差距小得多；单条查询的加速不能直接推算为索引加速。
英文补测复用了图片向量，没有再次测量图片编码时间；也未加载视觉模型，
因此英文报告的内存数据不能与中文完整模型组合直接比较。

本次测量为纯向量检索，不含 OCR、文件名匹配、整文件分块平均和融合排序。
图片仍是小规模公开样例集，不是通用英文图片准确率。
测的是 ONNX Q8/Q4，不能直接推断 GGUF 或 GPU 的速度和质量。
完整英文结果、各查询排名、向量及统计区间在
`artifacts/embedding-comparison/english/`；数据源版本在
`artifacts/embedding-comparison/manifest-data-en.json`。
